# Architecture Decision Record: Agent Enrollment and Identity

**Status:** Proposed  
**Date:** 2026-11-20

## Context

The Windows endpoint agent is the highest-risk component. It must enroll securely, maintain a stable identity, and only perform authorized actions.

## Decision (MVP)

1. Enrollment uses a one-time token generated by a tenant administrator.
2. On first contact the agent presents the token; the server issues a long-lived device certificate (or signed JWT device credential) bound to the tenant and a unique `device_id`.
3. Subsequent communication uses mutual TLS (or bearer token + device signature) with the device credential.
4. MVP agent is **read-only**: inventory collection and heartbeat only. No remote command execution.
5. Agent binaries are code-signed. Updates are signed and verified by the agent.

## Consequences

- Token-based enrollment is simple for pilots.
- Certificate/JWT device identity enables revocation and strong authentication.
- Read-only first release dramatically reduces attack surface.

## Open Questions

- Exact certificate lifetime and rotation cadence.
- Whether to support IdP-assisted enrollment in a later phase.
